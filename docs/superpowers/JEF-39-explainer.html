1 · Why this exists Everyone

JefeCheck could already put the same frame in front of several people and keep playback in step. What it could not do is let anyone mark that frame. Notes left the session as words — a phone call, a follow-up email, a paraphrase in a tracker — and arrived at the artist detached from the pixel they were about. Of every feature a review player is expected to have, this was the one most conspicuously missing.

2 · How we solve it Everyone

Complete the model JefeCheck has carried since 2006 rather than invent one. gfcReview, gfcRevision, gfcNote and gfcNoteText already existed as headers with empty method bodies. Two of their decisions were sharper than a fresh design would have been, and both were kept.

  • A round of notes can be locked. gfcRevision::locked is a review-workflow concept, not a storage detail — and locked rounds stay visible, because giving Wednesday's notes while seeing Monday's is the reason rounds exist.
  • A note belongs to one plate. gfcNote::quadID means markup in a 2×2 comparison sticks to the version it is about.
  • Geometry is normalised image space (0..1), never pixels. One representation serves the screen and the export, and notes survive pan, zoom, flip, flop and rendering at another resolution.
  • Annotations composite after the super-shader. Routed through it, a note's red would shift when exposure is pulled — the markup would start lying about itself.
  • Burn-in defaults off. A note baked into a delivery render is far worse than one the user has to tick a box for.

4 · How it fits the system Engineering

Domain. A gfcReview is keyed by one normalised media path and holds a sequence of gfcRevision rounds, each stamped with an author and a lock flag, each owning gfcNote instances that carry a quadID naming the plate they annotate, a from/to frame range the renderer filters on, and geometry supplied by whichever of gfcNoteStroke, gfcNoteArrow, gfcNoteBox or gfcNoteText the reviewer drew with.

Systems and data stores. The authoritative store is a .jnotes XML sidecar written beside the sequence by gfcNoteStore, falling back to ~/.config/jefecheck/notes/<sha1>.jnotes when the media directory refuses a write — render mounts are commonly read-only, and without that fallback the feature does not work at most facilities. The in-memory g_noteReviews vector in SequenceLoadBridge_qt.cpp is a derived cache lazily populated from that sidecar; gfcPlate::plateNotes is derived again, holding borrowed pointers into it for the renderer. Live sessions cross the RakNet message bus behind ITransport, using the same paired-message convention as the existing chat and pointer traffic.

Security. The server never trusts the author a client claims: gfcnetworkserver.cpp stamps it from nickNameAddressMap[peer] before caching or rebroadcasting, so a note cannot be attributed to someone else. Removal is honoured only from the note's author or the host. No credential is involved and no note data leaves the session or the local sidecar.

10 · Limitations Follow-up

  • Revision unlock does not propagate. A wire message exists for lock but not for unlock, so a host unlocking a round is a local-only change. Needs a symmetrical GFCNETID_REVISIONUNLOCK pair.
  • The text tool has no text entry. It creates a note and renders one, but there is no UI to type into it; the demo sets its string directly.
  • Two-process sync is unverified. Covered in section 7; the harness lives on another branch.
  • Stroke antialiasing is GL_LINE_STRIP width. Consistent-width AA needs triangle-strip expansion. Recorded in the spec as a known quality limit, not addressed.
  • Burn-in is skipped on forceSingleBufferedFX GPUs, which already lose colour correction in renders for the same structural reason.
  • Two bugs were found by looking at a screenshot, not by tests. 47 green assertions had nothing to say about either. Noted because it says something about where the coverage is thin.
